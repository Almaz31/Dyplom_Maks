# Аналітичне розширення «Обрію» · 20.10.2026

## Аудит

Збережено React/TypeScript/Vite, FastAPI/Python, SQLite, Leaflet, D3 Geo та Recharts. До змін уже працювали CSV/EM-DAT імпорт, погодні карти України і світу, глобальна аномалія GISTEMP, катастрофи України/GDIS, описова статистика, каталог та підготовлені прогнозні моделі Європи. Повний аудит і початковий план: [analytics-audit.md](analytics-audit.md).

Виявлені прогалини: немає історичних локальних аномалій, кореляцій, порівняння територій, окремого наочного контрольного блоку місячних прогнозів, XLSX/SVG аналітики та достатнього опису методів. Виправлено приймання порожнього значення GISTEMP за нуль, перевірку чисел/дат у світовій погоді й зайві погодні запити поза відповідним екраном.

## Додано

1. **Кліматичні аномалії.** Історичні значення та календарна норма, абсолютні й відсоткові аномалії опадів, z-оцінки, теплова карта, ковзне середнє, зміни рік до року, місячна/сезонна/річна агрегація, повнота даних. База 1991–2020 підтверджується за фактичними даними, не за написом у фільтрі.
2. **Статистичний аналіз.** Матриці Пірсона й Спірмена, вибір 2–4 змінних, сирі або позбавлені календарних середніх ряди, діаграма розсіювання, регресія, R², описова статистика, розподіл та кількість викидів. Немає непідтверджених p-значень.
3. **Прогнозування та аналітичні моделі.** Сезонний наївний метод і сезонна лінійна регресія, окремий хронологічний контрольний блок, MAE/RMSE, факт проти прогнозу, помилки, горизонт 1–36 місяців, емпіричні межі за достатнього калібрування. Старий прогнозний діалог і його артефакти збережено.
4. **Порівняння регіонів.** Дві–чотири території з одного набору, тільки спільні повні місяці, спільний графік та tooltip, KPI й таблиця, різниця між крайніми середніми. Окремі джерела не змішуються.
5. **Історія клімату території.** Повні річні температури й опади, річний тренд, різниця кінцевих років, місячні аномалії та сезонний контекст. Точки та індекси не видаються за станційну історію конкретного міста.
6. **Природна небезпека.** Тільки Natural з фактичного EM-DAT; частота, відомі наслідки, карта/таблиця областей, річні частоти й структура типів. Ваги змінюються користувачем. Без експозиції/вразливості не заявляється повний ризик; за невідомої тяжкості спільний індекс не рахується.
7. **Пояснення та відтворення.** Висновки формуються детерміновано з обчислених чисел. Є методологія, посилання на джерела, URL стану фільтрів і реальний числовий приклад.
8. **Експорт.** CSV та XLSX поточного розділу з фільтрами й метаданими; для прогнозу — історія, перевірка, майбутні оцінки й точність; для кореляцій — матриця, статистика й вирівняні місяці; для історії — річні дані й аномалії; для небезпеки — події/області/роки. SVG показаного графіка містить опис. Доступний браузерний друк.

## API

Усі нові маршрути читають існуючі файли й таблиці; не записують нових спостережень.

| Маршрут | Метод | Призначення |
| --- | --- | --- |
| `/api/analytics/sources` | GET | Набори, місця, доступні змінні, місяці та дата основного знімка/імпорту |
| `/api/analytics/report` | POST | Клімат, повнота, описова статистика, парні кореляції й річна історія |
| `/api/analytics/forecast` | POST | Місячний прогноз та перевірка з фіксованого початку |
| `/api/analytics/compare` | POST | Спільні місячні значення 2–4 територій |
| `/api/analytics/hazards` | POST | Відносний індикатор історичної небезпеки |
| `/api/analytics/export/{csv\|xlsx}?view=…` | POST | Експорт клімату, статистики, прогнозу, історії або порівняння |
| `/api/analytics/hazards/export/{csv\|xlsx}` | POST | Експорт природних подій, областей і частот |

Базовий запит:

```json
{
  "source": "nasa", "location": "country:UKR",
  "start": "2000-01", "end": "2025-12",
  "metric": "temperature", "baseline_start": 1991, "baseline_end": 2020,
  "level": "monthly", "rolling": 12, "season": "all",
  "variables": ["temperature", "precipitation"], "transform": "deseasonalized"
}
```

Для імпортованих даних `source = dataset:<id>`, `location = UA-XX`. Для прогнозу додаються `method: trend|naive`, `horizon: 1..36`, `test_months: 12..60`. Порівняння має `locations` з 2–4 різних місць одного джерела. Для індикатора потрібні `catalog`, дати `YYYY-MM-DD`, наявний `event_type` за бажанням, `frequency_weight`, `severity_weight` у межах 0–1, не обидві нульові.

## Методи та обмеження

- Погодні добові дані групуються в SQLite: усі календарні дні потрібні для повного місяця окремої змінної. Пропущені місяці позначаються null, зокрема після фактичного кінця знімка. NASA приймається як підготовлений місячний реаналіз.
- Річні/сезонні середні зважені за днями; опади сумуються. Для зими використано грудень попереднього року. Повний календарний рік/сезон повинен повністю входити в обраний інтервал.
- Норма кожної календарної групи потребує всіх років бази, щонайменше 10. Стандартна 30-річна база потребує повних 30 років із початком у році, що закінчується на 1. Це строга перевірка локального набору, не сертифікація ВМО.
- `A=x−μ`; опади у відсотках — `100(x−μ)/μ` за μ≠0; `z=(x−μ)/σ` за σ>0. z не інтерпретується як доказ нормального розподілу. Ковзне середнє не перестрибує пропуски.
- Регресія OLS за фактичним часом, мінімум три пари. Спірмен має середні ранги для однакових значень. Сталі змінні не отримують вигаданого коефіцієнта. Викиди за 1,5 IQR не вилучаються. Кореляція не встановлює причинності.
- Часове розділення прогнозу: останні 12–60 місяців повністю відкладено. Немає випадкового перемішування або використання контрольного блоку в його прогнозуванні. Після оцінювання фінальна модель переоцінюється на всій обраній історії.
- Емпіричні межі — 5%/95% квантілі помилок з навчальної частини для того самого горизонту та календарного місяця початку. Мінімум 10 помилок; без них межі відсутні. Покриття не гарантоване, можливі структурні зміни клімату.
- Індикатор небезпеки = нормоване зважене середнє min–max-компонент частоти та середніх відомих загиблих у пов’язаних подіях. Події без області не локалізуються штучно. Втрати багатообласних подій не видаються за втрати кожної області. Пропущена тяжкість не дорівнює нулю. За нульової її ваги використовується тільки частота.

Методичні першоджерела: [норми ВМО](https://community.wmo.int/en/activity-areas/climate-services/climate-products-and-initiatives/wmo-climatological-normals), [перевірка часових рядів](https://otexts.com/fpp3/toolbox.html), [рангова кореляція](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html), [обмеження EM-DAT](https://doc.emdat.be/docs/known-issues-and-limitations/).

## Джерела та зберігання

NASA POWER/MERRA-2 (375 точок, 1981–2018 + фактичне доповнення), імпортовані ERA5/Open-Meteo й EM-DAT; старі GISTEMP та GDIS збережені. Немає нових джерел, платних API, секретів або бібліотек. Схема SQLite **не змінена**, міграції не потрібні. Вихідні CSV/XLSX/JSON та старі артефакти моделей не перезаписуються.

NASA знімок кешується в пам’яті з інвалідацією за шляхом/розміром/часом зміни файлів. Щоденні SQLite-записи агрегуються на сервері; до браузера надходять місячні ряди. Застарілі клієнтські запити скасовуються; фільтри мають затримку перед автоматичним перерахунком. Прогноз/порівняння/індикатор запускаються явно.

## Запуск і перевірка

```powershell
npm.cmd --prefix frontend run build
powershell -ExecutionPolicy Bypass -File stop.ps1
powershell -ExecutionPolicy Bypass -File start.ps1
```

Сайт: `http://localhost:8001/?page=analytics`. Для первинного встановлення використовується наявний `setup.ps1`. Збірка розділена на кешовані частини: код входу близько 72 kB, карти 150 kB, React 224 kB, графіки 454 kB до gzip. Це поділ і можливість повторного кешування, не виміряне прискорення завантаження. Попередження Vite про пакет понад 500 kB усунуто.

Серверні тести: `.venv/Scripts/python.exe -m pytest -q`. Браузерні: у frontend `npx playwright test` із `PLAYWRIGHT_BASE_URL` на тестовий сервер. Серверні тести використовують тимчасову SQLite, браузерні — окрему SQLite у `logs/analytics-qa`, не користувацьку БД.

Остаточні результати:

- **36 серверних тестів пройдено** (13 нових для аналітики): контрольні середні/медіани/σ, ранги, Пірсон/Спірмен, регресія, нульова норма/мінливість, пропуски, сезонна межа року, ковзне вікно, MAE/RMSE, відсутність витоку майбутніх даних, повнота кінця знімка, індикатор і його ваги, відбір тільки природних подій, експорти всіх видів, перевірка чисел зовнішньої погоди.
- **24 браузерні тести пройдено**, у тому числі всі старі 18 та нові 6: карти/глобус, імпорт, шкали, пагінація, старі прогнозні моделі, нові аналітичні екрани, фільтри/URL, XLSX/SVG, помилка API без застарілих графіків, методологія.
- **Виробнича збірка успішна**, TypeScript без помилок, Vite без попередження про великий пакет.
- Додаткова Chromium-перевірка шести нових розділів: ширини **390, 768, 1100, 1440 px**, без горизонтального переповнення й `pageerror`. Збережено `analytics-desktop.png` та `analytics-mobile.png`.
- `git diff --check` без помилок. Залишається попередження наявної залежності Starlette/TestClient про httpx; на результат тестів воно не вплинуло.
- Робочий сервер перезапущено на **8001**; перевірено HTTP 200 і відповідь `/api/analytics/report` із 312 місяцями та підтвердженням бази 1991–2020.

Відтворення чисел: `.venv/Scripts/python.exe scripts/reproduce_analytics.py`; результат — [reproducible-analysis.md](reproducible-analysis.md) і [JSON](reproducible-analysis.json).

## Свідомо не додано

ARIMA/Prophet, CO₂, тиск, населення й вразливість не додаються заради кількості можливостей: для них немає підготовленої перевіреної інтеграції. Добові екстремуми не відновлюються з місячних даних. PDF не генерується сервером — доступний друк/збереження браузером. Кількісних Core Web Vitals та випробувань багатокористувацького навантаження не проводилось. Це дослідницька платформа, не служба оперативних попереджень.
