# Аудит і план аналітичного розширення · 20.10.2026

## Виявлена реалізація

React 19 / TypeScript / Vite; FastAPI / Python; SQLite. Карти Leaflet, глобус D3 Geo, графіки Recharts. Імпорт CSV з валідацією, одиницями, дублікатами та звітом; імпорт EM-DAT Excel через openpyxl. Дані зберігаються в datasets/observations та disaster_datasets/disasters; є індекси за територією і датами. Зміни схеми не потрібні.

Існують погодний екран України, світова погода, NASA GISTEMP, українські та світові катастрофи, каталог, методика, прогнозний діалог Європи. Analytics уже рахує середнє, медіану, стандартне відхилення сукупності, квартилі, тренд і R². Стандартне відхилення має визначений дільник n; R² не визначений для сталої залежної змінної. Кореляцій, строгих місячних норм, порівняння територій та експортів аналітичних XLSX/SVG немає.

Джерела: ERA5 / Open-Meteo (точки біля міст України, 2000–2025 і окремі додаткові роки); NASA POWER / MERRA-2 (375 точок, 1981–2018 плюс окремий фактичний знімок 2019–2025 та неповний 2026); GISTEMP v4; EM-DAT; GDIS; geoBoundaries/OSM/Natural Earth. Вихідні запити й дати одержання збережено у samples. Прогнозні артефакти мають контрольні відбитки, часові перевірки, MAE/RMSE, компактні відповіді та кеш. Нові обчислення не змінюють їх навчання.

## Проблеми та рішення

- Поточна місячна агрегація допускає неповні суми: зберегти робочі старі екрани, у новій аналітиці враховувати лише повні календарні місяці для кожної змінної та показувати відхилені.
- 2000–2025 не забезпечує норму 1991–2020. Не домішувати окремі роки й не називати коротку вибірку 30-річною нормою. NASA може забезпечити норму після перевірки знімків.
- NASA GISTEMP парсер приймає порожній рядок як число 0: виправити явною перевіркою числового формату.
- Погодні запити виконуються навіть поза погодним екраном: обмежити активним екраном.
- Кеш світової погоди не перевіряється повторно; немає перевірки числових діапазонів відповіді: перевіряти і мережеві, і локальні відповіді.
- Повноцінний risk score не обґрунтований без експозиції та вразливості. Надати прозорий індикатор історичної частоти/наслідків із часткою відомих значень.
- Розширити наявну навігацію через один аналітичний центр із вкладками, зберегти старі розділи й діалог.

## Послідовність

1. Спільне серверне ядро статистики, місячної якості, аномалій, кореляцій і сезонного тренду; контрольні тести.
2. API джерел і вибірок, аналітичний звіт, порівняння, перевірка прогнозів, індикатор небезпеки, CSV/XLSX.
3. Аналітичний центр: клімат, статистика, прогнозування, порівняння, історія території, природні катастрофи; спільні фільтри й відтворювані URL.
4. Розширена методологія, огляд, SVG-експорт графіків, детерміновані пояснення.
5. Серверні та браузерні тести на ізольованій БД, збірка, мобільна перевірка, відтворюваний приклад із реальними результатами, звіт про межі реалізації.
