# Обрій — кліматична лабораторія України

Локальний прототип дипломної з погодою й катастрофами. React + TypeScript + FastAPI, SQLite та локальні файли. Одна адреса для сайту й API: **http://localhost:8000**.

## Світовий режим — 12.10.2026

### Кнопка «Передбачення» — 14.10.2026

Інтерфейс повернуто до навчання **1981–2018**. Кнопка розташована в хедері, виділена теплим золотистим кольором. Після вибору фільтрів потрібно натиснути **«Почати магію»**; автоматичного запиту при відкритті немає. Під час запиту обертається індикатор, повторне натискання вимкнено. Зміна року, місяця або моделі очищає результат до нового запуску. Довгі пояснення, перемикач навчання до 2025 та порівняння з фактом прибрані. Збережено градієнтну карту Європи, окремі графіки значень і аномалій, CSV і таблицю по 10 рядків. Запит інтерфейсу: `{"year":2026,"month":0,"cutoff":2018,"compact":true,"method":"temporal"}`. Для карти й таблиці передаються короткі оцінки; історія вибраної точки завантажується окремо через `point_id`. Результати кешуються в клієнті та сервері. Нижче описано також збережені скрипти експериментального оновлення до 2025; вони не використовуються поточним інтерфейсом.

За замовчуванням використовується **тренд + авторегресія відхилень** (`method:temporal`). Для кожної точки, місяця й показника за останніми 20 відомими роками обчислюється тренд; його залишки моделюються регуляризованою AR(2), яка враховує два попередні відхилення. Сума модулів коефіцієнтів обмежена 0,98 для стійкості. Це дає нелінійне продовження оцінок без вигаданого випадкового шуму; умовні середні на довгому горизонті можуть наближатися до тренду. Аномалії є різницею прогнозу та норми 1981–2010. Кандидат проходить ті самі часові перевірки 2005–2011, калібрування 2012–2014 та окремий тест 2015–2018. MAE й діапазони беруться з перевірок саме обраної моделі. Є таблиця конкретних оцінок і меж для кожного року, з двома десятковими знаками.

Лінійний сезонний тренд доступний через `method:trend`. `method:auto` залишає автоматичний вибір за MAE й може обрати постійне сезонне середнє. Обрана користувачем модель не оголошується кращою за автоматичний вибір без перевірки; точні випадкові стрибки погоди та хвилі спеки на роки вперед не відомі.

Поточна модель охоплює **375 точок у 46 країнах і територіях**: сітка європейської суші 2° у межах 34–80° N / 26° W–60° E, включно з Ісландією й європейською частиною Росії до Уралу. Для малих держав є окремі точки; їхня вага в загальноєвропейському індексі дорівнює нулю, щоб не завищувати площу. Межі області й перелік країн задані у `scripts/fetch_europe_full.py`. Це покриття сіткою, а не прогноз кожної адреси.

Дані: `samples/europe-weather-full.json.gz`, 1981–2018, NASA POWER Monthly API / MERRA-2. Опади NASA в мм/день перетворюються на місячні суми з урахуванням календарних днів. Оригінальні відповіді — `samples/europe_monthly_raw/`. Підготовка: `python scripts/fetch_europe_full.py`.

Навчання: `python scripts/train_europe_model.py`. Навчаються pooled Ridge-регресія та гістограмний градієнтний бустинг для прямих горизонтів 1–12 років. 29 ознак містять координати, сезонність, горизонт, попередні значення всіх 4 показників, середні, мінливість і тренди. Ознаки кожного прикладу бачать лише дані до його початку. Ridge використовує 297 000 прикладів; бустинг — фіксовану навчальну вибірку 25 000, seed 42. Базові моделі — сезонне середнє 10 років і тренд 20 років.

Вибір моделі: прогнозні цілі **2005–2011**, за середньою MAE всіх 12 горизонтів і всіх точок. Тип моделі залишається однаковим для всього майбутнього ряду місяця/показника, щоб перемикання моделей не створювало штучні стрибки. Додатковий кандидат — сезонний тренд + Ridge, навчений на залишках від тренду. Архівне калібрування: **2012–2014**, незалежна перевірка: **2015–2018**, із власним навчанням до кожного початку прогнозу. Діапазон використовує три калібрувальні роки та 20 сусідніх точок; це емпірична похибка, не гарантований імовірнісний інтервал.

Збережений експеримент оновленого навчання до 2025 містить 391 500 прикладів для Ridge, горизонти 2026–2030. Поточний інтерфейс використовує лише режим до 2018, горизонти 2019–2030. Експериментальні додаткові дані: `samples/europe-weather-observed.json.gz`, повні роки 2019–2025 і доступні повні місяці 2026 до серпня, на тій самій сітці й з того самого NASA POWER / MERRA-2. Неповні місяці з NASA fill value відкидаються для всієї фіксованої сітки; річних спостережень 2026 ще немає.

Оновлена модель зберігає вибір сімейства за валідацією 2005–2011; калібрування — 2019–2021, незалежний тест — 2022–2025 з навчанням тільки до початку кожного прогнозу. **2026 не використовується для навчання, вибору або калібрування.** Факт 2026, похибка «прогноз − факт» та аномалії показані окремо. Місячне середнє не дорівнює денному максимуму хвилі спеки. Аномалія — різниця зі спільною нормою 1981–2010 для відповідного місяця/року; вона не зіставляється напряму з іншою базою, наприклад 1991–2020 у Copernicus. Машинне навчання не обирається примусово, якщо базове середнє краще на валідації.

Відтворення оновлення: `python scripts/fetch_europe_observed.py`, потім `python scripts/train_europe_updated.py`. Артефакти оновленої моделі — `samples/europe_models/updated/`. API: `POST /api/world/prediction` з `{"year":2026,"month":7,"cutoff":2025}`; `cutoff:2018` — архів, `month:0` — весь рік. Перевірочні метрики належать історичним folds, а не фактам 2026.

Карта завантажує лише `frontend/public/europe-countries.geojson`, без світової підкладки. Температура та інші показники відображаються суцільним градієнтом IDW за шістьма сусідніми вузлами, з маскою європейської суші. Це візуальна інтерполяція 375 модельних оцінок. Для вибору — **56 маркерів**: одна точка на країну/територію, дві для 10 великих країн (площа понад приблизно 250 тис. км²); при виборі іншого вузла представницький маркер переміщується до нього без збільшення кількості. Клік по території обирає найближчий вузол цієї країни. Можна перемкнути градієнт між прогнозом і фактом. Підготовка контурів: `python scripts/build_europe_map.py` (потрібен Shapely лише для підготовки).

Артефакти: `samples/europe_models/models.joblib` (ваги), `forecasts.npz` (прогнози, помилки всіх кандидатів і діапазони), `report.json` (split, розміри, MAE/RMSE, fingerprint даних). Кнопка читає ці артефакти й не тренує модель повторно. Дані та fingerprint перевіряються; при зміні набору потрібно повторити навчання. Проміжні `fold-*.joblib` кешуються локально і виключені з Git.

Попередній набір із 19 точок і простими трендами збережено для відтворення раннього прототипу; за наявності повного набору застосунок використовує навчені моделі вище. Нижче — опис цього попереднього варіанта.

Кнопка відкриває окремий розрахунок температури, опадів, вологості й вітру в Європі на **2026** (або 2019–2030) рік. Можна вибрати конкретний місяць або весь рік. Для місяця модель використовує тільки той самий календарний місяць 1981–2018; опади — місячна сума, решта — місячні середні. Карта Європи містить клікабельні точки оцінок. Це навчальна статистична оцінка зі зрізом історії **до 2018 року**, а не оперативний прогноз чи фактичні дані 2026. Каталог катастроф GDIS у моделі погоди не використовується.

- Джерело прогнозного набору: **NASA POWER / MERRA-2**, доба UTC, 1981–2018. 19 фіксованих точок регулярної сітки з кроком 8° у межах 38–70° N / 8° W–40° E, маска європейської суші. Це грубий індекс вибірки, не точне середнє всієї Європи; дрібні країни й території між вузлами сітки можуть не бути представлені.
- `samples/europe-weather-1981-2018.json` містить повні річні агрегати та метадані. `samples/europe_forecast_raw/` зберігає стиснені оригінальні відповіді й URL для відтворення. Оновлення: `python scripts/fetch_europe_forecast.py`. Мережа потрібна лише для підготовки даних, не для кнопки.
- NASA-поля: T2M (°C), PRECTOTCORR (мм/день → річна сума), RH2M (%), WS10M (м/с). Неповний рік відкидається; пропуски й NASA fill value не підмінюються нулями. Регіональний індекс — зважене за cos(latitude) середнє за фіксованою сіткою; річні опади в ньому є середнім річних сум у точках, а не сумою по континенту.
- Порівнюються 5 моделей: історичне середнє, лінійний тренд, середнє останніх 10 років, тренд останніх 20 років і згасаючий тренд (коефіцієнт 0,85). Вибір — за MAE перевірок із рухомим початком та тим самим горизонтом, що й оцінка: для 2026 це 8 років. Останні 3 перевірки виключено з вибору моделі; їхня MAE показується окремо й порівнюється з базовим середнім. Кожна перевірка бачить лише роки до свого початку. Дані після 2018 не використовуються. Кращу точність не припускаємо автоматично: інтерфейс повідомляє, якщо на відкладеній перевірці модель поступилася базовій.
- Діапазон — ±80-й процентиль абсолютних історичних помилок, обчислений окремо для кожного горизонту, а не гарантований довірчий чи прогнозний інтервал. Він не враховує всі можливі структурні зміни клімату. Для вологості застосовано межі 0–100%, для опадів і вітру — нижню межу 0.
- Є історичний ряд, пунктирна оцінка, MAE відкладених перевірок, порівняння моделей, точки на карті Європи, таблиця з пагінацією та CSV з місяцем. API: `POST /api/world/prediction`, тіло `{"year":2026,"month":1}`; `month:0` — весь рік.

Джерело: [NASA POWER Daily API](https://power.larc.nasa.gov/docs/services/api/temporal/daily/). Метод перевірки: [Forecasting: Principles and Practice](https://otexts.com/fpp3/toolbox.html).

Перемикач «Україна / Світ» зберігає масштаб при переході між вкладками «Дослідження» й «Катастрофи».

Глобус показує контури країн Natural Earth 1:110m. При виборі міста, довільної точки або маркера країна виділяється, а її назва українською показується над глобусом. Для точки в океані виділення знімається. Межі України узгоджено з українською картою проєкту, включно з Кримом. Геометрія збережена локально у `frontend/public/world-countries.geojson`; `scripts/fetch_world_countries.py` дозволяє відтворити файл (Shapely потрібен лише для підготовки ресурсу).

- Погода: температура, опади, вологість, вітер; місто або довільна точка на 3D-глобусі, період до 5 років. ERA5 через Open-Meteo, доба UTC, вітер у м/с. Дані точок не є середніми для країн чи світу.
- `samples/world-weather.json` — реальний автономний приклад за 2024 рік для восьми міст на різних континентах. Оновлення: `python scripts/fetch_world_weather.py`. Інші точки завантажуються за запитом і кешуються в `data/world_weather/`. Кольорові маркери й підписи відповідають показнику та періоду; сірі маркери не мають даних за вибраний період.
- NASA GISTEMP v4 доступний окремим показником «Глобальна температурна аномалія»; база 1951–1980, лише повні роки.
- Світові катастрофи: окремий історичний GDIS із `samples/gdis/original.csv`, 1960–2018. Фільтри країни, типу та років, клікабельні маркери й таблиця. Маркери — центри адміністративних територій; кілька геолокацій однієї події не дублюють її в статистиці. GDIS не містить наслідків і точних дат у цьому файлі та не є повним переліком катастроф світу.
- API: `/api/world/weather`, `/api/world/weather-reference`, `/api/world/disasters`. Український Excel EM-DAT використовується окремо.

### Катастрофи

Імпортовано наданий користувачем public_emdat_custom_request_2026-09-29_c15f18a1-0997-403a-9ce3-b733ae1bf60c.xlsx: **81 унікальна катастрофа за 2000–2025 роки**. Історичний GDIS не використовується в українських метриках чи карті; він підключений окремо в режимі «Світ».

Вкладка **Катастрофи**: карта кількості подій, фільтри території/групи/типу/періоду, річний таймлайн, графік початку подій, таблиця, картка події й CSV-експорт. Показники: число унікальних катастроф, загиблі, постраждалі, відомі номінальні збитки. Біля наслідків показується кількість відомих і пропущених оцінок. Метрики охоплюють інтервал фільтра, а таймлайн змінює кадр карти й таблиці.

- Українські записи відбираються за ISO=UKR. Повторний імпорт того самого оригіналу не дублює каталог.
- Географія: адміністративні одиниці GADM/GAUL і явно названі області в Location. База відповідності зберігається в `backend/disasters.py`; неоднозначні села не геокодуються навмання.
- **13 подій** не мають однозначної області: вони зберігаються в загальних підсумках і таблиці. Визначені зв’язки охоплюють **26 територій**. Це покриття каталогу, а не твердження, що в інших місцях катастроф не було.
- Події з кількома областями рахуються один раз у національній статистиці. Сума чисел на карті може перевищувати число катастроф; втрати події не розподіляються між областями.
- Числові маркери — центри областей із кількістю пов’язаних подій, не точні місця катастроф. Координатні маркери використовують лише Latitude/Longitude з оригіналу.
- **2 записи** мають неповну дату початку. Межі можливого місяця/року використовуються для фільтрації з явним збереженням точності дати.
- Порожні наслідки зберігаються як невідомі. Total Damage ('000 US$) множиться на 1000. Скоригована сума зберігається окремо; номінальні суми різних років не подаються як зіставні ціни одного року.
- На погодній карті є перемикач **Шар катастроф**. Події фільтруються за місячним кадром або всім вибраним періодом.

Завантажити ще один Excel можна кнопкою **EM-DAT Excel**. API: /api/disaster-uploads, /api/disaster-datasets, /api/disaster-datasets/{id}/analysis, /export, /original. Опис полів: https://doc.emdat.be/docs/data-structure-and-content/emdat-public-table/.

## Перший сценарій

1. Відкрити сайт; натиснути **«Відкрити приклад ERA5»** або **«Завантажити CSV»**.
2. Для власного CSV зіставити дату, область та погодні показники, одиниці й географічний зміст.
3. Перевірити дані. Скачати помилки, виправити файл або явно погодитися пропустити відхилені записи.
4. Імпортувати. Вибрати область на карті чи у списку, показник та інтервал дат.
5. Пересунути таймлайн або увімкнути анімацію. Карта відображає місячний кадр; графік та калькулятор — вибраний інтервал. Є режим карти за весь інтервал.
6. Натиснути **«Скачати вибірку CSV»**. Оригінал можна скачати у каталозі датасетів.

## CSV

UTF-8, кома / крапка з комою / табуляція, до 20 МБ і 1 000 000 рядків. Добові значення: одна територія за одну дату. Мінімум дата, область і один числовий показник.

```csv
date,region,temperature,precipitation,humidity,wind
2024-01-01,UA-46,4.5,2.1,80,3.2
```

Цей рядок пояснює формат і не є науковим спостереженням. Реальний приклад міститься в `samples/era5_2024.csv`.

Області: українські назви (`Львівська`, `Львівська область`) або ISO-коди UA-XX. `UA-30` — м. Київ, `UA-32` — Київська область. Дати ISO або ДД.ММ.РРРР. Числа з десятковою комою підтримуються, якщо CSV правильно екрановано або розділено крапкою з комою.

Перетворення: K → °C, м → мм, частка → %, км/год → м/с. Пропуски зберігаються, не підміняються нулями. Дублікати дата/територія відхиляються з явним звітом. Фізично неможливі значення та нескінченності відхиляються; екстремуми не видаляються механічно.

## Реальний приклад і географія

- `samples/era5_2024.csv`: 2 196 добових записів за 2024 рік для точок біля Львова, Києва, Одеси, Харкова, Дніпра та Сімферополя. Модель ECMWF ERA5 через [Open-Meteo](https://open-meteo.com/en/docs/historical-weather-api), CC BY 4.0. Доба UTC. Це реаналіз для точок, **не середні по областях**. Заливка карти відображає їх адміністративну прив’язку.
- Точні параметри, координати й дата отримання: `samples/source.json`; оригінальна відповідь: `samples/raw-open-meteo.json`.
- Повторне завантаження: `python scripts/fetch_sample.py`; потрібен інтернет, числа не генеруються.
- Межі: [geoBoundaries gbOpen](https://www.geoboundaries.org/), OpenStreetMap / Wambacher, ODbL 1.0. Усі 27 територій, включно з Кримом, Києвом і Севастополем. Метадані й ліцензія — `frontend/public/boundaries-source.json`. Геометрія зберігається локально; зовнішніх тайлів немає.

## Формули

Калькулятор використовує всі наявні добові записи вибраної області та інтервалу. Середнє — сума / кількість значень; опади — сума. Повнота — кількість днів із показником / кількість календарних днів. Пропущені дні залишають розриви. Інтервали понад 1500 днів агрегуються на графіку помісячно; підсумки калькулятора залишаються добовими. Опади з пропусками є неповною сумою. Експорт містить наявні очищені записи, а не вигадані рядки для пропущених дат.

## Структура й межі

`backend/` — API та розрахунки; `frontend/` — React; `data/` — SQLite й оригінали користувача; `samples/` — реальний приклад; `tests/` — перевірки.

Локальна версія без авторизації та публікації в інтернеті. Невеликі CSV перевіряються синхронно в серверному робочому потоці. SQLite обрано для запуску без Docker; PostgreSQL/PostGIS та фонові завдання — наступне масштабування. Excel EM-DAT підтримується для катастроф. NetCDF, погодинні записи, просторове зважування та прогнози — наступні етапи. Дані користувача не відправляються зовнішнім API.
